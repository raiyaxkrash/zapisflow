# Оформление Mini App: редактор владельца

## Модель и публикация

Используются существующие `MasterSettings.branding`, контактные поля `MasterSettings` и `MasterBrandAsset`. Текущий Alembic head — `2026_10_05_0029`; новая миграция не нужна. Оформление относится к проекту и не требует отдельного тарифного разрешения.

Владелец открывает **Ещё → Настройки → Оформление**. Разделы редактора: бренд и изображения, цвета и тема, тексты, видимость клиентских разделов, контакты. Черновик хранится в форме; публичные изменения появляются только после сохранения. Удаление изображения также выполняется при сохранении. Сброс требует подтверждения и возвращает стандартные настройки.

`POST /api/miniapp/master/branding/save` принимает multipart:

- `payload`: JSON с `branding`, `contacts`, `delete_logo`, `delete_cover`;
- `logo`, `cover`: необязательные файлы.

Все файлы и поля проверяются до изменения данных. Настройки, контакты и изображения сохраняются в одной существующей транзакции Mini App. Повтор сетевого запроса использует тот же ключ идемпотентности, включая хеши файлов. Старые GET/PUT, asset и reset endpoints сохраняются для совместимости.

## Предпросмотр и темы

Локальный предпросмотр использует клиентскую главную, реальные услуги и черновые контакты. Его кнопки не создают запись и не меняют роль или сессию. Акцент и тема применяются к контейнеру предпросмотра независимо от темы панели мастера. System учитывает Telegram colorScheme, вне Telegram — системную тему браузера. Чёрный или белый текст на акценте выбирается по контрасту. Подпись «Работает на ZapisFlow» обязательна.

При сохранении клиентский context обновляется; вход на главную также перечитывает настройки. Публичные изображения возвращаются с `Cache-Control: no-store`. API публикации не синхронизирует профиль Telegram. После сохранения владелец может отдельно нажать «Обновить профиль Telegram»; см. TELEGRAM_BOT_BRANDING.md.

## Безопасность

- Только владелец проекта: проверка session, tenant, Origin и CSRF остаётся общей с Mini App.
- Цвет — только `#RRGGBB`; тексты ограничены по длине и не принимают HTML. Контакты проходят существующую нормализацию.
- PNG/JPEG/WebP: максимум 4 MiB исходника, 16 млн пикселей. SVG запрещён. Проверяется фактический формат, изображение нормализуется Pillow в WebP без исходных метаданных.
- Логотип ограничен 320×320, обложка — 1200×600; результат каждого файла не более 256 KiB. Оригиналы не сохраняются.
- Новый multipart endpoint проверяет имя и расширение файла; пользовательское имя никогда не становится путём хранения.
- Публичные картинки являются материалами бизнеса; приватные настройки не выдаются через media endpoint.

## Проверки

Backend: `pytest -q`, включая owner-only, tenant isolation, атомарность двух uploads, невалидный второй файл, повторы и удаление assets. Mini App: `npm test` и `npm run build`, включая безопасный предпросмотр и multipart retry. Marketing: существующие тесты и сборка.

Локальные скриншоты и browser fixtures находятся вне Git в `.artifacts/miniapp-redesign/phase-6/`. Они используют mock Telegram/API и настоящий production bundle. Настоящие Telegram iOS/Android/Desktop, реальная загрузка через production-сессию и публикация не проверялись в этой фазе.
